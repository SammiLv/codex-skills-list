# 钉钉组长例会议题

## 1. 目标

从本周周一到周五的钉钉群沟通和个人聊天记录中，整理需要在组长例会上沟通、确认、推进或升级的议题，并写入每周一下午 `组长例会` 这个日程自带的会议纪要。

除非用户明确改口，不要创建钉钉文档、钉盘文档或普通周报文档；输出目标必须是日程里的会议纪要或日程详情中承载会议纪要的字段。

## 2. 默认范围

- 时区：`Asia/Shanghai`
- 沟通观察范围：本周周一 `00:00` 到本周周五 `23:59:59`
- 数据源范围：默认同时筛选工作群沟通和当前用户个人聊天记录；个人聊天只提炼与组长例会相关的议题，不写入私人链接、账号、密钥、无关闲聊或敏感原文
- 会议定位范围：优先找本周或最近一次即将发生的周一下午 `组长例会`
- 会议标题关键词：`组长例会`、`每周组长例会`、`周一组长例会`
- 默认身份：当前用户本人；不要把群里高频出现的人名误当成当前用户

如果用户给了明确日期范围、指定群、指定会议标题或指定日程链接，优先使用用户提供的信息。

## 3. 工具使用原则

优先使用 DingTalk MCP，不要默认操作钉钉桌面 UI。

### 3.1 群沟通和个人聊天证据

先检查当前会话中可用的 DingTalk 群聊、消息、机器人、日志或相关 MCP 工具 schema。

- 如果有可读取群聊消息的工具，按时间范围查询相关工作群。
- 如果有可读取个人聊天或单聊消息的工具，按同一时间范围筛选当前用户个人聊天记录中的工作事项。
- 如果只有群元数据工具，没有消息读取能力，说明消息源受限，并询问用户是否提供群名、截图、导出的聊天记录，或允许使用桌面 UI。
- 如果需要使用 Computer Use 读取钉钉桌面聊天记录，先确认用户允许，因为这会读取实际聊天界面；用户已授权的情况下，可以同时查看群聊和个人聊天列表。
- 不要发送群消息、创建群、修改群设置或触发机器人通知。

### 3.2 日程和会议纪要

使用 `dingtalk-calendar-mcp` 或当前可用的日程 MCP：

1. 用 `list_calendar_events` 查询周一下午附近的日程。
2. 用标题关键词筛选 `组长例会`。
3. 对候选日程调用 `get_calendar_detail`，确认标题、时间、组织者、参会人、已有描述/纪要字段。
4. 写入前检查 MCP schema 是否存在明确的会议纪要字段或会议纪要工具。
5. 如果存在专门的会议纪要创建/更新工具，优先使用它。
6. 如果没有专门纪要工具，但日程详情显示纪要内容由 `description` 或 `richTextDescription` 承载，可用 `update_calendar_event` 写入对应字段。
7. 如果无法确认任何日程字段会写入“会议纪要”，停止并说明当前 MCP 不支持可靠写入会议纪要；不要退而创建钉钉文档。

如果本周周一下午 `组长例会` 日程不存在：

- 先向后查找下一次周一下午 `组长例会`，避免误判周期日程。
- 如果仍不存在，创建一个周一下午的 `组长例会` 日程，再创建或写入会议纪要。
- 创建日程时只填必要信息：标题、时间、时区、纪要内容；不要擅自邀请参会人或预订会议室，除非用户明确要求。

## 4. 议题筛选规则

只保留适合和组长沟通的事项，优先级从高到低：

1. 需要组长拍板、协调资源、推动跨组协作的事项。
2. 群里出现的阻塞、风险、延期、口径不一致、依赖未闭环。
3. 用户被点名、被安排、明确承诺或需要反馈的事项。
4. 需要在例会上同步进展、结果、下周计划的重点项目。
5. 可以沉淀为流程规范、复盘改进、人员协作规则的问题。
6. 个人聊天中由用户自己记录、提醒或转发的本周工作议题，例如会议压缩、方案讨论、流程调整、跨组协调、待组长确认的个人想法；这类内容要转写成可讨论议题，不要把私人聊天原文照搬进纪要。

剔除以下内容：

- 纯通知、闲聊、表情、打卡、系统消息。
- 与当前用户职责无关，且不需要组长介入的群信息。
- 已经明确闭环且不需要例会同步的小事项。
- 无法从证据中判断为工作事项的猜测。
- 个人聊天中的私人链接、账号、密钥、订阅地址、个人隐私和与工作无关内容。

## 5. 输出到纪要的格式

写入会议纪要时使用中文，简洁正式，保留来源线索但不要大段引用聊天原文。

推荐结构：

```markdown
## 本周需与组长沟通议题

### 1. 待决策/需拍板
- 议题：...
  - 背景：...
  - 需要组长确认：...
  - 来源：群名 / 日期 / 关键词

### 2. 风险/阻塞
- 议题：...
  - 当前状态：...
  - 需要支持：...
  - 来源：群名 / 日期 / 关键词

### 3. 进展同步/协作事项
- 议题：...
  - 本周进展：...
  - 下一步：...
  - 来源：群名 / 日期 / 关键词
```

如果某一类没有内容，可以省略该小节。每个议题尽量包含 `议题`、`背景/状态`、`需要组长做什么`、`来源`。

## 6. 写入方式

写入前先读取已有日程详情和已有纪要内容：

- 如果已有 `本周需与组长沟通议题` 小节，替换该小节，保留其他会议纪要内容。
- 如果没有该小节，在原有纪要末尾追加新小节。
- 如果原纪要为空，直接写入完整结构。
- 如果字段长度有限，保留高优先级议题，删减来源描述，不要删除议题本身。

写入后再次读取日程详情确认内容存在。最终回复用户时说明：

- 覆盖的沟通日期范围
- 写入的日程标题和时间
- 写入议题数量
- 未覆盖的数据源或受限原因

## 7. 安全边界

- 默认只读取群沟通和日程，最后只修改目标例会的会议纪要。
- 不要创建钉钉文档作为替代输出。
- 不要向群聊发送任何内容。
- 不要删除或取消日程。
- 不要擅自修改会议时间、参会人、会议室或循环规则。
- 如果日程修改需要组织者权限而失败，向用户说明权限问题，并把待写入纪要内容直接展示在会话中。
